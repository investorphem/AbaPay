# x402

{% hint style="info" %}
**Zero setup** — no AbaPay account, ever, for this path.
{% endhint %}

An independent agent — say, an FX agent holding a Celo wallet — never needs to know AbaPay
exists in advance. The whole exchange happens over plain HTTP, challenge and response.

## The flow

1. Holds or uses a Celo wallet.
2. Calls AbaPay's quote / pay_bill endpoint directly.
3. Gets `402 Payment Required` back, with the exact price and asset.
4. Signs an EIP-3009 `transferWithAuthorization` with that same wallet — nothing else.
5. Retries the request with the signed authorization attached.
6. AbaPay settles on Celo via Celo's own x402 facilitator and vends the bill.

{% hint style="warning" %}
**Never required for this path:** an account, Agent Hub, API key, PIN, wallet-signature link.
{% endhint %}

{% hint style="info" %}
**Signing capability and running this flow are two different things.** Any self-custody wallet
on Celo can produce the EIP-3009 signature step 4 needs — there's nothing AbaPay-specific about
it. But driving the three round trips (price → 402 challenge → signed retry) is a different
requirement: a wallet's ordinary send screen doesn't do that on its own today, something has to
— `abapay-sdk`, a CLI, or an agent (see [the SDK chapter](sdk.md)). A wallet with no such client
gets a plain 402 and nowhere to go with it, so **the challenge response carries a `hint` field**
(outside the x402 spec, ignored by any client that doesn't look for it) pointing a person stuck
there at the ordinary guided flow instead: **[abapays.com](https://www.abapays.com)** needs no
x402 at all — connect, see the live price, approve, sign.
{% endhint %}

{% hint style="info" %}
**Account verification happens after settlement, not before.** For electricity, bank
transfer, JAMB, and cable (except Showmax), AbaPay checks the meter/account/smartcard number
against the biller only once your payment has actually settled on-chain — not while pricing
the 402 challenge. This is deliberate: checking beforehand would let anyone probe that
lookup for free with no wallet and no payment. A wrong-but-plausible account number still
settles the on-chain transfer, then fails verification and is refunded automatically — so
double-check the account details before paying, since a bad one costs a settle-then-refund
round trip rather than being caught upfront.
{% endhint %}

## Request & response

`POST /api/pay/x402` — no `X-PAYMENT` header yet:

{% code title="Request — no payment attached" %}
```json
{
  "serviceID": "mtn", "serviceCategory": "AIRTIME",
  "network": "MTN", "billersCode": "08012345678",
  "nairaAmount": 1000, "token": "USDC",
  "blockchain": "CELO", "wallet_address": "0xYourAgentWallet..."
}
```
{% endcode %}

{% code title="← 402 Payment Required (real field names)" %}
```json
{
  "x402Version": 1,
  "error": "Payment required",
  "accepts": [{
    "scheme": "exact",
    "network": "eip155:42220",
    "asset": "0x48065fbBE25f71C9282ddf5e1cD6D6A887483D5e",
    "payTo": "0x5df8aE2B963165b735B18Ca86B1ea448d2AA032C",
    "maxTimeoutSeconds": 86400,
    "extra": { "name": "Tether USD", "version": "1", "primaryType": "TransferWithAuthorization" }
  }],
  "hint": "This is a machine-to-machine x402 endpoint. If your wallet can sign but has no client that runs the challenge/sign/retry sequence, pay this bill instead at https://www.abapays.com — no x402 required there. Full x402 flow: https://docs.abapays.com"
}
```
{% endcode %}

{% code title="Retried with X-PAYMENT: <base64 signed authorization> → 200 OK" %}
```json
{
  "success": true, "status": "SUCCESS",
  "tx_hash": "0x91a3...4f2c", "request_id": "req_...",
  "purchased_code": null, "units": null
}
```
{% endcode %}

USDC, USD₮, and USA₮ all settle via Celo's own x402 facilitator — each implements EIP-3009. Full
field reference: [openapi.json](https://agents.abapays.com/openapi.json).

## Don't hand-roll the signing

`abapay-sdk`'s `payBillViaX402()` does exactly the three requests and one signature above —
pass it a viem account and the bill details, get back the settlement result. See [the SDK
chapter](sdk.md).
